# 選題靈感案例庫

本案例庫專為參與「打造你的第一個 AI 助理」工作坊的同學準備，只是發想參考，不是必選題。各方向皆可結合 **OpenClaw + 生成式 AI / Skills / MCP / 自動化工作流** 進行實作與發揮。

---

## 🌿 方向一：永續校園
> **核心概念**：以 SDGs 為方向，針對校園內的環境、能源、減塑或社會教育議題，運用 AI 工具提出具體可行的解決方案。

### 案例 A：校園碳足跡與冷氣能耗智控助理
- **目標受眾**：總務處營繕組、各系所辦公室、自習室管理員。
- **痛點情境**：教室與自習空間常有無人開冷氣、溫度過低造成能源浪費等問題；手動巡檢耗時費力。
- **AI 助理切入點**：
  - 讀取校園電表 API / 課表排程 CSV。
  - 比對「預約使用時段」與「實際用電量」，自動產出節能優化建議報告。
  - 當特定空間無課卻持續高耗電時，透過 Telegram 發送安全提醒給管理員。
- **可用 Prompt 示範**：
  ```text
  請讀取「sample-data/教室課表與用電.csv」。
  找出今日 18:00 後「無排程卻用電量 > 15kWh」的教室清單。
  整理成一份節能通報草稿，包含：教室代碼、異常時段、建議巡檢優先級。
  涉及關閉電源等動作，請標註「需由巡查人員現場確認後手動操作」。
  ```

### 案例 B：二手教科書與減塑物資循環配對助理
- **目標受眾**：全校學生、綠色校園社團。
- **痛點情境**：每學期二手書買賣資訊散落於 Dcard、各系社團，交易撮合效率低且易產生棄置浪費。
- **AI 助理切入點**：自動解析教科書課綱清單，比對求購與轉讓需求，產生去個資化的媒合草稿。

## 🚀 方向二：新服務點子
> **核心概念**：以校園為出發點，發掘潛在需求或痛點，運用 AI 工具設計具實用潛力的服務或產品原型。

### 案例 A：跨院系專長媒合與專案發包平台助理
- **目標受眾**：有意參與跨領域專案、專題研究、新創專案的東吳學生。
- **痛點情境**：商學院學生找不齊技術夥伴，巨資/資管學生缺少題目與商業模式設計者。
- **AI 助理切入點**：
  - 學生上傳個人公開專長技能與想做的題目方向。
  - AI 助理進行向量語意比對，推薦互補度最高的三位跨系夥伴候選人。
  - 自動生成破冰合作提案草稿與責任分配架構。
- **可用 Prompt 示範**：
  ```text
  請讀取「sample-data/學生社團調查.csv」中的技能與興趣欄位。
  針對「想開發校園共享傘 App」的提案，推薦三位具備不同互補專長（前端、行銷、營運）的學生代表背景。
  說明推薦理由與建議合作分工；嚴禁推測或揭露真實個人聯絡方式。
  ```

### 案例 B：個人化校園職涯與實習履歷健檢教練
- **目標受眾**：即將畢業或尋找實習的大三、大四學生。
- **痛點情境**：學生不清楚校內修課經驗如何轉化為企業職缺所需的關鍵字與亮點。
- **AI 助理切入點**：比對學生修課歷程與企業 JD (Job Description)，標出能力缺口並產出個人化自傳精修建議。

## ⚡ 方向三：流程改善
> **核心概念**：鎖定校園中的低效率流程或使用者痛點，透過 AI 工具提出自動化或數位化的具體改善方案。

### 案例 A：跨校區（外雙溪 ⇄ 城中）選課衝堂與交通排程智能助理
- **目標受眾**：修讀跨領域學程、雙主修、輔系之全校學生。
- **痛點情境**：兩校區接駁車班次、通勤時間與各系選課限制繁雜，學生手動排課極易衝堂或趕不上公車。
- **AI 助理切入點**：
  - 讀取東吳大學開課清單 CSV 與校車時刻表。
  - 輸入想修讀的課程名稱，自動檢查時間衝突、跨校區通勤緩衝（預留 45 分鐘）。
  - 產出推薦課表並隨附教務處官方開課代碼以供人工複核。
- **可用 Prompt 示範**：
  ```text
  請讀取「sample-data/校園 FAQ.md」與課表資料。
  針對一位想同時修讀雙溪英文系與城中資管系課程的大二學生：
  1. 列出兩校區週三下午的排課時間表
  2. 計算城中到雙溪的接駁車銜接時段是否具備至少 40 分鐘緩衝
  3. 產出選課可行性分析與選課系統操作叮嚀
  ```

### 案例 B：學生社團場地借用與活動企劃檢核助理
- **目標受眾**：課指組同仁、全校 100+ 個學生社團負責人。
- **痛點情境**：社團活動企劃書格式不一、場地規範未看清，導致重複退件與補件，耗費大量行政時間。
- **AI 助理切入點**：比對學務處場地使用規範，產出企劃書格式、用電限制、噪音分貝與保險需求的檢核清單草稿，最後由承辦人判斷。

## 🧭 方向四：校園資源導讀

> **核心概念**：把散落的校內資源整理成「找得到、說得清楚、附出處」的導讀，不替使用者做任何判斷或決定。

### 案例 A：校內協助資源導讀助理（高風險議題，只做資源指引）
- **目標受眾**：不知道該找哪個單位協助的學生。
- **痛點情境**：學生不清楚諮商、學務或行政窗口的預約流程，不知道第一步該找誰。
- **AI 助理切入點**：
  - 只整理校內公開資源的單位、預約方式與官方連結，並附出處。
  - **不做**情緒支持對話、心理評估、診斷或分流；這些必須由專業人員處理。兩天的課堂實作不足以安全處理危機情境。
  - 只要訊息涉及自傷、他傷或人身安全，固定顯示緊急求助資訊，不繼續一般對話。
- **可用 Prompt 示範**：
  ```text
  你是一位「校內資源導讀助理」，只提供公開資源的單位、預約方式與官方出處。
  遵守原則：
  1. 不提供心理評估、診斷、醫療或用藥建議，也不進行諮商式對話
  2. 資料未記載的單位或時段，回答「目前資料未記載，請洽官方窗口」
  3. 訊息涉及自傷、他傷或人身安全時，只回覆以下緊急求助資訊：
     校安中心緊急專線
     雙溪校區 (02) 2881-7734、0910-270-050
     城中校區 (02) 2389-0952、0910-270-060
     衛福部安心專線 1925（24 小時）
  ```

### 案例 B：國際生校園生活與雙語法規導覽助理
- **目標受眾**：外籍交換生、學位生、國際處同仁。
- **痛點情境**：校內大量公告、選課介面與行政表格僅有中文，國際生就讀初期容易面臨資訊孤島。
- **AI 助理切入點**：即時雙語對齊校務規章、簽證延期步驟與居留證辦理 FAQ。

## 🧰 專案起步包：把各方向做成同一條 MVP

每人只選擇一個「使用者的一次提問」作為 MVP；所有案例均採相同安全介面：

```text
個人 Telegram 白名單訊息
  → 本機唯讀 Skill（只讀指定 sample-data）
  → 含來源的「待人工核准」草稿
  → 人工確認後才考慮任何外部動作
```

| 方向 | 最小資料集 | 建議本機 Skill | Telegram 測試情境 | 風險限制與驗收 |
| --- | --- | --- | --- | --- |
| 🌿 永續 | `學生社團調查.csv`（課堂替代資料） | 活動／資源摘要 Skill | 「本週有哪些可參加的永續活動？」 | 僅摘要公開資料；輸出需有檔名來源，無資料不得編造。 |
| 🚀 新服務點子 | `學生社團調查.csv` | 去個資化的專長整理 Skill | 「我想找行銷與前端合作，下一步怎麼做？」 | 不推薦或揭露真實個人聯絡方式；只產出合作邀請草稿。 |
| ⚡ 流程改善 | `校園 FAQ.md` | 選課／活動 FAQ Skill | 「跨校區選課要注意什麼？」 | 不讀密碼、不代送選課；時程或資格標示待人工確認。 |
| 🧭 資源導讀 | `校園 FAQ.md` | 校園資源導讀 Skill | 「我想找校內協助資源，該從哪裡開始？」 | 不作醫療、法律或行政決定；高風險情境改提供官方求助方向。 |

### 共通的三筆同儕測試

1. **可回答**：測試者問一個資料內有答案的問題，驗收回答與來源。
2. **資料缺漏**：測試者問一個資料內沒有答案的問題，驗收「資料未記載」而非捏造。
3. **越權請求**：測試者要求報名、傳送、寫檔或提供個資，驗收拒絕與人工核准閘門。

## 💡 如何在專案中運用這些案例？
1. **挑選痛點**：從上方挑選一個最有共鳴的子題，或參考架構自訂校園議題。
2. **界定資料範圍 (Context)**：將公開資料整理為 Markdown 或 CSV 放入 `sample-data`。
3. **建立 OpenClaw 流程**：設計 Prompt 範本、設定唯讀邊界，並加入 Human-in-the-loop 人工審核關卡。
4. **目標使用者測試**：邀請 5 位目標使用者實機測試，保留真實的成功率、滿意度與修正紀錄，再匯出專案企劃書。範例 CSV 是虛構資料，不能當成自己的測試結果。
