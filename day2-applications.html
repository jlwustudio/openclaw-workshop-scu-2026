S09 / READY + BUDGET09:00–09:15

開始前：確認資料與工具都在正確位置

請先執行 openclaw gateway status，確認 Runtime 是 running；不是的話照 安裝手冊「確認背景服務」處理（昨天改用雙視窗前台執行的同學，今天要再開一次視窗 A）。上午 S10–S11 沿用 Day 1 的 workspace，可在 sample-data 讀寫與產出 Markdown 檔；S12 起改用只能讀取的課堂唯讀 workspace。若遇到無法預期的套件問題，隨時切換到講義的文字備援路徑。

macOS / Linux 終端機
ls ~/.openclaw/workspace/sample-data

若顯示 No such file or directory，請照 安裝手冊 Part C 步驟 2 重新複製（Linux 請確認今天是在同一位使用者環境下執行）。

Windows PowerShell
Get-ChildItem "$HOME\.openclaw\workspace\sample-data"

若顯示找不到路徑，請照 安裝手冊 Part C 步驟 2 重新複製。

今日額度檢查

打開 aistudio.google.com，左側點 Rate Limit，打開右上角 All models，確認 Gemini 3.5 Flash Lite 與 3.1 Flash Lite 都還在免費方案內。每日額度在台灣時間下午 4 點重置，昨天下午 4 點之後的用量會算進今天；兩個模型各 500 次，今天全天估計用 50–90 次。表格顯示的是過去 28 天的最高峰，不是即時用量。

找到 Gemini 3.5 Flash Lite 那一列，右邊三欄都寫成「用量 / 上限」：RPM（每分鐘請求，上限 15）、TPM（每分鐘 token，上限 250K）、RPD（每天請求，上限 500）。這裡的用量是 28 天內的最高峰，所以 RPD 不等於今天已經用掉的次數；只要上限還是 15／250K／500，就代表仍在免費方案內。上課時常撞到 TPM 上限，就在對話中輸入 /new。

再用下列指令確認模型沒有被換掉：

openclaw models list --provider google

gemini-3.5-flash-lite 那一列的 Tags 要有 default；沒有的話照 安裝手冊「指定模型」重新設定。

S10 / WEB09:15–09:35

搜尋與整理：把網頁變成可用的事實

網頁搜尋能補足記憶盲點，但也容易帶回大量噪訊；重點不是抓多，而是精準抓取事實、標出來源，以及保留人工查證的欄位。

看一看

講師示範如何從抓取網頁原始內容，到把整理後的表格輸出成 Markdown 檔。

講師 Demo

提供一份指定網址，請助理只摘錄指定欄位（名稱、日期、對象、來源網址）。

寫寫看

自己寫一段限制輸出格式的提示詞，和鄰座比較；不必送出執行。

查驗

對照原始網頁，確認助理有沒有把「推測」寫成「事實」。

請幫我讀取這頁網址：［貼上網址］。 不要摘要整頁，只抓取四個欄位：活動名稱、日期、對象、來源網址。 如果網頁中找不到某個欄位，請明確寫「未標示」，不要自行推測。 讀不到指定網址時直接告訴我，不要改讀其他網站。
  1. 先給指定網址：讀取 sample-data/網頁練習網址.txt，裡面是指定的東吳子網站網址（東吳首頁 www.scu.edu.tw 因網站憑證問題讀不到，所以不使用）；練習時只用指定的網址，不執行全網開放式搜尋。
  2. 只抓取原始事實：要求助理只抓取可追溯、可核對的原始事實，不加入未授權的評價或情緒字眼。
  3. 標記資料來源：每一筆資料都要包含原始網址；對於模糊、推測或需人工確認的項目，標記「需人工確認」。
  4. 存成 Markdown 檔：將整理結果寫入 workspace，方便後續比對與查核。
請讀取 workspace 裡的「sample-data/網頁練習網址.txt」， 從中選擇第一個網址，擷取一則校園活動資訊。 請用四欄輸出：活動名稱、日期、對象、來源網址。 如果某欄位沒在網頁中提及，請寫「未標示」； 讀不到指定網址時直接告訴我，不要改讀其他網站； 不要在這次對話中寫檔案。
草稿確認無誤後，請把整理結果用 Markdown 表格格式， 寫入 workspace 的「網頁摘要紀錄.md」。 表格欄位：活動名稱、日期、地點／方式、適合對象、來源網址、需人工確認事項。 寫入後顯示檔案路徑，並提醒我開啟檔案檢查是否完整。

查證三問

這項資訊來自哪一段網頁？有沒有不可靠的延伸推論？如果有缺漏，是否清楚標示「未標示」？

常見錯誤與防範

將「可能舉辦」誤寫為「確定舉辦」、把過期公告當作最新資訊、把非官方討論當成官方公告；指定網址讀不到時，助理自行改讀其他網站。

實測案例：抓到的是過期活動

課前試跑時，助理成功從東吳子網站擷取活動名稱、日期與對象，但抓到的是 2026 年 3 月已經結束的活動，「需人工確認事項」欄卻沒有標出已過期。格式正確不代表內容可用：請一定要核對日期。

S11 / DATA09:35–10:30

處理資料：CSV 使用者回饋分析與我的題目問答

讓 AI 助理處理資料時，最怕「指令不清毀壞原檔」或「對數據妄下推論」。本節以 CSV 數據示範校園專案中關鍵的「目標使用者測試與量化回饋分析」，最後 20 分鐘寫好自己題目的問答，作為下午 MVP 的資料。檔案整理計畫改為課後選做。

1

分類原則

依日期、類別或狀態劃分，建立清楚可讀的資料夾名稱。

2

先講計畫

列出檔案原本在哪裡、打算搬到哪裡，經確認後才執行。

3

量化回饋

計算測試成功率與滿意度，作為專案落地優化的依據。

  1. 分析使用者測試數據：讀取 sample-data/使用者測試回饋範例.csv（虛構範例），計算成功率、平均滿意度與核心痛點。
  2. 課後選做：檔案整理計畫：先在 Finder／檔案總管把 workspace 的 sample-data/待整理 複製一份並改名為 練習，只在 練習 操作；不存取桌面、下載或個人文件。
  3. 先看後動：先讓助理讀取清單並說明計畫，確認無誤後才授權移動或建立檔案。
請讀取「sample-data/使用者測試回饋範例.csv」。 請為校園 AI 助理專案進行快速量化與質化分析： 1. 計算總體「操作成功率 (%)」與「平均回答滿意度 (1-5 分)」 2. 列出滿意度最低（< 4 分）的受試案例盲點 3. 根據受試者建議，提出 2 項具體的 Prompt 或系統優化方案 請用 Markdown 表格與重點摘要列出。
（課後選做）請讀取「sample-data/練習」資料夾下的檔案清單。 請先列出檔名規則、分類規則、遇到無法判斷檔案時的處理方式， 以及如何保留原始檔；先不要寫程式或移動檔案。
範例數據是虛構的：這份 CSV 只用來練習分析方法，不能當作你自己的測試成果。要證明助理好用，請找 5–10 位目標使用者實際操作，保留真實紀錄與修正歷程。

10:10–10:30 撰寫我的題目問答（不用模型）

下午 S17 你會把這些問答加進自己 Day 2 workspace 裡的 FAQ 副本，讓 Telegram Bot 回答你自己題目的問題。現在先用文字編輯器寫好，存在桌面（例如 我的題目問答.txt），不需要呼叫模型。題目可用 Day 1 的 MVP 畫布，或從 選題靈感案例庫 挑一題。

  1. 寫 3–5 條問答：照下方格式，從 Q9 開始編號。全部是虛構練習資料，不放個資、真實電話或未公開校務內容。
  2. 至少 1 條保留不確定：例如「具體日期與名額需人工確認」，練習助理誠實標示。
  3. 高風險題目只做指引：心理、醫療、法律、獎助等題目，答案只能指向官方窗口，不做判斷或建議。
  4. 先寫三個測試題與預期結果：可回答（答案在你的問答裡）、資料缺漏（和題目相關但問答沒寫）、越權（要求代辦或提供個資）。先寫預期，再測試，才能判斷對錯。

課後選讀：個人化的便利，也要有資料界線

本練習不設定真實帳號記憶，而是練習設計一條可公開、可刪除的回覆偏好。這樣既能理解個人化，也不會把私人資料放進課堂工具。

可公開的偏好

回答格式、希望先摘要再給選項、公開的學習目標、提醒的語氣。

不應提供的資料

密碼、學號、電話、住址、健康或財務資訊、他人的資料與未公開校務內容。

在這次課堂任務中，請只遵守這條可公開偏好： 先用三行摘要，再給我可選的下一步。 不要要求、記錄或推測任何私人身分、帳號或聯絡資料。 請用「如何整理一份活動公告」展示一次這條偏好如何影響你的回覆。
S12–S14 / BUILD A LOCAL SKILL10:45–12:00

每人建立一個本機最小 Skill

Skill 能把重複流程做成可測試的小工具；MCP (Model Context Protocol，模型上下文協議) 則是連接外部工具與資料的協議，兩者都不等於權限控管。本課程不安裝外部套件：每位同學只以講師指定的本機範本，建立一個限制於課堂工作區、僅開放讀取工具、使用虛構資料的最小 Skill。

10:45–11:00 全班同步切換 workspace：講師在投影畫面上一步一步帶，依 課堂唯讀設定 建立唯讀 workspace 並套用工具限制；助教巡場，先做完的同學協助鄰座。上午 S10–S11 產出的檔案留在 Day 1 的 workspace；切換後助理只能讀取，不能寫檔、執行指令或瀏覽網頁。11:00 起進行 Skill 測試。
觀念 1

🧩 Skill：教它怎麼做

一份 SKILL.md，包含名稱、描述（description）與步驟指引。助理依描述判斷何時載入；它說明「這類任務怎麼做」，但不能授予或限制權限。

觀念 2

🔌 MCP：讓它接得上

連接外部工具與資料來源的開放協議（2026-07-28 版規格改為無狀態核心並強化授權）。它負責「接得上」，不保證安全；本課不安裝、不實作 MCP。

觀念 3

🛡️ 工具政策：決定能做什麼

OpenClaw 的工具設定（今天的 read-only.json）與外部服務自己的權限，才決定助理實際能做什麼。所以驗收看工具紀錄，不看模型怎麼說。

01 建立

依 課堂唯讀設定 複製可載入的 SKILL.md 成品 與 FAQ 到獨立 workspace。

02 限權

套用只允許 read 的工具設定與工作區路徑限制；確認寫入、執行、瀏覽及傳訊工具不可用。

03 測試

用三個指定測試問題驗收：可回答、資料缺漏、越權／個資要求。

04 整合

以自己已驗收的 Skill 作 MVP 的資料處理核心，保留來源與人工核准規則。

  1. 先列規格：使用者輸入是一段自由文字；輸出必須含回答、來源檔名與「資料未記載」的誠實回覆。
  2. 再建立最小版本：只使用 sample-data/校園 FAQ.md，不可增加外部資料源。
  3. 最後以證據驗收：完成三個測試案例，把提問、輸出、來源與是否通過寫入 MVP 工作單。
我想使用老師指定的 Skill「［名稱］」。 請先說明：它的用途、可能會讀寫哪些資料、如何停止或移除。 在我同意前，不要安裝。
請讀取「sample-data/校園 FAQ.md」。 我想把它做成可重複使用的「東吳選課與活動 FAQ 小工具」。 先寫規格：輸入、輸出、允許讀取的檔案、不該做什麼，以及三個測試案例。 請使用已依 sample-data/本機最小Skill範本.md 安裝的 scu-campus-faq-helper。未載入時直接說明，不要假裝成功或修改設定。

個人交付

驗收問題

輸入不同問法會不會得到可追溯的回答？找不到答案時會不會誠實說明？遇個資或外部動作是否拒絕並停在草稿？

講師示範：同一個問題、三種上下文

講師在已限制權限的示範環境，用同一題「社團場地借用要怎麼申請？」各開一個新對話。你不用操作，邊看邊記下差異。

| 情況 | 回答差在哪？ | 有沒有附來源？ | 工具紀錄：讀了什麼？有沒有呼叫被擋下？ | | --- | --- | --- | --- | | 1. 沒有資料（只憑模型知識） | | | | | 2. 指定資料（使用 FAQ Skill） | | | | | 3. 資料裡藏了惡意指示 | | | |

重點：資料選擇決定答案有沒有根據；資料本身也可能夾帶指示，要看工具紀錄確認權限真的擋住，模型口頭說「不會照做」不算證據。

為什麼使用者測試是專案落地的關鍵？

做 AI 專案最看重「真的有使用者用過嗎？好用在哪？哪裡出錯？」。以下 4 個步驟能幫你在提案時拿出高說服力的佐證：

  1. 定義 3 個核心情境任務：例如「請大一同學查詢選課 FAQ」、「請社團幹部試排空堂」、「請同學找活動並辨識需人工確認欄位」。
  2. 邀請 5 位跨系同學實機操作：觀察他們在哪一步卡關、耗時多久、有沒有產生 AI 幻覺。
  3. 記錄量化指標：計算「任務成功率 (%)」、「平均滿意度 (1-5分)」與「操作秒數」。
  4. 展現優化對照：列出「發現的問題 ➔ 調整 Prompt / Context 限制 ➔ 優化後的滿意度提升」，這就是最紮實的落地驗證！

《行政院及所屬機關（構）使用生成式AI參考指引》合規要點

  • 出處標註義務：引用之校務規章、活動內容需明確加註原始公告來源。
  • 機敏資料保護：嚴禁使用個人帳號、密碼、通訊錄或未公開機密訓練或測試模型。
  • 不可全自動決策：涉及學生權益（如選課送出、懲處判定）必須經由 Human-in-the-loop 人工審核。

1. 具體目標 (Goal)

避免模糊的「幫我處理」，改用明確動詞如「請整理」、「比對」、「計算」或「產出表格」。

2. 充份脈絡 (Context)

指定資料範圍（如「只讀取 sample-data/學生社團調查.csv」），並給予明確邊界條件（如「不要改動原始檔案」、「遇欄位缺失標註未標示」）。

3. 格式與驗收 (Output & Definition of Done)

指定交付成果格式（如「四欄 Markdown 表格」或「三句摘要」），並要求先提供計畫草稿經人工確認後才執行。

1. 不只聽 AI 說，要看檔案事實

AI 回覆「已建立完成」並不代表真正成功。一定要親自打開 Finder/檔案總管或 cat 檢查實體檔案內容與檔名。

2. 保留完整的 Log 與報錯訊息

遭遇錯誤時，將完整終端機報錯訊息、HTTP 狀態碼或程式 Log 複製給 AI，不要只說「程式壞掉了」。

3. 縮小改動範圍 (Minimal Modification)

要求 AI 每次只修復一個問題，修正前先列出改動計畫，嚴禁盲目重試或一次大幅重寫全域程式碼。

1. 人在迴圈閘門 (Human-in-the-loop Gate)

涉及 Telegram 推播、信件寄出、檔案刪除或系統改寫等不可逆動作時，強制加入人工審查同意關卡。

2. 隱私與個資保護

嚴禁存取或傳輸學生個人學號密碼、通訊錄、私人對話或未公開校務秘密資料。

3. 幻覺防禦與出處可追溯

所有輸出的事實與數據均需隨附來源網址或檔案名稱；若無資料支持，強制標記「資料不足，請以官方公告為準」。
